# Troubleshooting

- **`athena: no config yet: run athena init first`**: `athena hq` ran without a terminal (a key binding, a script) before any config existed. Run `athena init` once in a terminal.
- **`✗ herdr: not found` after installing it**: the installer put it in a folder your shell does not search yet. Open a new terminal, or add that folder (often `~/.local/bin`) to `PATH`.
- **`herdr server did not start`**: read `logs/herdr-server.log` in the state dir; `herdr status server` shows which socket athena expects. A server from an older herdr: `herdr server stop`, then `athena`.
- **`athena` prints JSON instead of attaching**: it attaches only from a terminal outside herdr (no `HERDR_ENV`, stdin and stdout a tty). Inside herdr, `athena hq` focuses the space instead.
- **Workers in the wrong folder, or the hooks not seeing a worker**: `athena config show` lists the worktree root they use; an `ATHENA_WORKTREE_ROOT` in your shell wins over the file. Keep herdr's `[worktrees] directory` the same.
- **After a herdr restart, a worker's report draws as plain text, or a board column shows a dead terminal**: a worker spawned before athena registered resume commands came back as a bare `claude --resume`. The mod and the status hook still find it by its worktree; its next SessionStart (any `/clear`, compaction or resume) registers its full command. The board watcher moves the columns to the live terminals on its own (`athena board sync --force` does it at once). See [How it works](how-it-works.md#after-a-herdr-restart).
- **`no agent named 'athena' is reachable`, or `athena status` says `messaging socket missing`**: Claude Code registers each session in `~/.claude/sessions/<pid>.json` with the unix socket SendMessage reaches it on (`messagingSocketPath`, under `/tmp/cc-socks/`). When that file is gone while the session runs, nobody can SendMessage it until its Claude restarts. `athena status` and the watch flag it for HQ and every live worker. `athena doctor --fix` (every minute under `athena service`) restarts the session on its own conversation, which gives it a new socket: HQ with `athena hq restart --no-update`, a worker in its column, each once it is idle with an empty input box. By hand: `athena hq restart --no-update` for HQ. Workers' reports still arrive meanwhile: their ATHENA-REPORT line is the report, and they try SendMessage once.
- **`config.json is not valid JSON`**: fix the file, or move it away and rerun `athena init`.
- **The watch mod is not running in HQ** (`pgrep -fl 'athena watch --tagged'` shows nothing): Claude Code is older than 2.1.286, mods are turned off, or the plugin was not reloaded since an update. HQ falls back to Monitor; see [How it works](how-it-works.md#fallback).
- **`go` is missing**: the dashboard needs Go; `athena hq` carries on without it. See [Dashboard](dashboard.md#failure-modes) for its other failure modes.
- **`athena service install` while a herdr server already runs** (one your terminal started): the herdr job's `herdr server` exits with `herdr server is already running`, and launchd or systemd tries again every 30 s (`logs/service-herdr.log` fills with that line). Once the old server stops, the job's server takes over and resumes the agents. Hand over at a quiet moment: `herdr server stop` stops the old server and every agent in it, and herdr resumes them under the job.
- **`athena doctor` says `gave up after 3 repairs in the last hour`**: the same repair failed three times; doctor stops trying for an hour so a broken part does not restart in a loop. The detail before it says what failed (a dashboard port in use, a resume refused). Fix that, then `athena doctor --fix`. `doctor.json` in the state dir keeps the attempts; deleting it resets them.
- **HQ's Claude is gone and `athena` does not start a fresh one**: athena brings HQ back on its saved conversation (`hq.json` `session`). If that resume fails (`claude --resume <id>` refused the id), it says so instead of starting a new conversation by accident. Start a fresh HQ on purpose with `athena hq rotate`, which writes the handoff first.
- **A restart, rotation or retire says someone is typing**: the pane's input box holds text not yet sent, and athena never types `/exit` over it. Send or clear it, then retry; `athena retire --force` goes ahead anyway.
